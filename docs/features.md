# ✨ Features

[← Back to README](../README.md) · [Usage](usage.md) · [Settings](settings.md) · [Architecture](architecture.md)

- **Zero-Latency Dictation:** Powered by Groq's `whisper-large-v3` for near-instant speech-to-text. Long dictations stream — chunks are transcribed while you're still speaking, so releasing the key types almost instantly. A local **silence gate** (on by default) means a recording or streaming chunk with no speech is never uploaded — saving API calls and stopping Whisper from inventing text out of silence; the dBFS threshold is adjustable in Settings.
- **Voice Commands:** Say "new paragraph", spoken punctuation ("comma", "question mark"), "scratch that", or "all caps … end caps" while dictating. Each rule is edited as a **phrase → effect** row in Settings (with a bulk paste box), and fed to the polishing model so it can interpret fuzzy phrasing.
- **Import & Transcribe Audio Files:** Bring in existing recordings — voice notes from a chat app (wav, mp3, m4a, **ogg/opus**, flac, webm) — through a dedicated **Transcribe Audio** window (menu bar → *Transcribe Audio File…*, or drag files onto the Catalog to open it pre-loaded). The window has a **drop zone + file picker**, a **live per-file progress list**, and an **org/project assignment** applied to the batch. Each file is transcribed (uploaded to Groq as-is, so formats Core Audio can't read still work; on-device fallback when Groq is off/unreachable), given an **AI-generated title**, gets the **same AI enrichment a live meeting does** (summary, action items, structured extraction, unanswered questions, chapters — per your Meetings settings), and is written as a **meeting note filed under the file's own recording date** (from the file's metadata), then added to the Catalog. There you can relink it, **Move it to Dictation** (if it wasn't really a meeting), or delete it. Max file size is configurable (default 50 MB).
- **Per-App & Per-Site Styles:** Force a specific writing style for a given app (edited as rows of bundle-ID + style, with an **Add app…** menu that lists your running apps) or website (host + style rows) — e.g. always use the Messaging style in Slack, or the Email style on Gmail.
- **Call Detection:** When Zoom, Teams, Webex, Slack, or a browser call (Google Meet) starts using your microphone, GhostWriter offers to start Meeting Mode — and offers to stop and save the notes when the call ends.
- **Quick Notes (⌃⌥J):** Toggle-dictate a thought from anywhere into a per-day notes file — transcribed, polished, timestamped, with click-to-open notifications.
- **Meeting Templates:** Twelve built-in meeting types — grouped in the picker as **Sales & Customer** (Customer Call, Discovery Call, Solution Demo, Solution Scoping), **Delivery & Project** (Project Kickoff, Planning), **Team & Internal** (Standup, 1:1, All-Hands, Brainstorm), and **Other** (Lecture / Webinar, General) — each extracting their own summary sections, chosen right in the start-meeting dialog. Need something else (interview, retro, …)? Add it as a custom template. Edit any template's **summary sections and follow-up guidance**, or **add your own templates** (custom name + sections + guidance) in Settings.
- **Key-Field Extraction:** Beyond the prose summary, each meeting type pulls the **fields that matter for it** into a **Key Details** section and machine-readable YAML front-matter — a customer call's deal stage, budget, timeline, decision maker, and next step; an interview's recommendation, key strength, and key concern; a 1:1's sentiment and focus-next-time; a planning session's target date and top risk. **Categorical** fields (deal stage, recommendation, sentiment) are also mirrored into `tags:` so you can **filter by them in the Catalog** with the normal tag filter, and every field is Dataview-queryable in Obsidian. On by default (network required); uses the cheap lightweight model.
- **Context-Aware Polishing:** Detects the app you're typing in (e.g. Slack, Mail, Xcode) and uses a Llama model (default `llama-4-scout`, configurable) to format dictation appropriately — casual for Slack, formal for Mail, code-friendly for IDEs. Every writing style is **editable**, you can **add your own styles**, and a global default covers unrecognized apps.
- **Meeting Mode:** Captures system audio via CoreAudio **process taps** (no screen-recording permission required) alongside your microphone, producing a timestamped, speaker-labeled (**You** / _Them_) transcript.
- **Meeting Summaries:** When a meeting ends, an AI summary (TL;DR, decisions, action items) is appended to the notes automatically, and a notification lets you click straight into the file. In Local-only mode the summary is generated on-device (Apple Intelligence) instead. **Long meetings are handled by map-reduce**: rather than clipping to the last stretch (which would drop the opening), the whole transcript is condensed in chunks first — preserving every decision, action, and number — so an hours-long meeting is summarized end-to-end, not just its tail.
- **Sourced Summaries:** Summary points carry the transcript **timestamp** they came from (e.g. "Agreed to ship Friday [00:14:02]"), so you can jump back to the exact moment to verify — and the citation requirement itself keeps the model honest.
- **In-Meeting Bookmarks:** Press **⌃⌥B** during a meeting to mark the moment — an inline `★` marker lands in the transcript, and a timestamped **Bookmarks** jump-list is written at the end so you can find the parts that mattered.
- **Topic Chapters:** Optionally segment a finished meeting into 3–8 titled, timestamped chapters (a `# Chapters` jump-list) so long transcripts are navigable. One extra AI call per meeting; cloud-gated and toggleable.
- **Structured Extraction:** Beyond action items, the summary can pull out **Decisions** and **Risks & Blockers** as their own sections (Open Questions has its own toggle). Toggleable in Settings.
- **Unanswered Questions:** Extracts the questions that were raised in the meeting but never got a clear answer — your ready-made follow-up list — into the note's single **Open Questions** section, written as tick-off checkboxes (`- [ ]`) so each can be marked answered later. This is produced as part of the summary pass (one generation, no duplicate round-trip), using a strict "asked but never answered" judgment. Cloud-gated and toggleable.
- **Keyword Radar:** Keep a **watchlist** of terms — competitors, product names, risk phrases (managed as removable chips in Settings, with a bulk paste/edit box for long lists) — and every finished meeting is scanned **locally** (works offline) for them. Hits are surfaced in a **Mentions** section with counts and mirrored into `tags:`, so you can filter the Catalog by which meetings mentioned a competitor. No network, no AI cost.
- **Keyword Radar Insights:** A cross-meeting rollup of those watchlist hits, in the **Catalog** (sidebar → Track → **Keyword Radar**). Add terms **right here** with the inline field (no need to open Settings), then a **stats strip** (terms shown · total mentions · meetings scanned) tops a list where each term shows total mentions, how many meetings mentioned it, and when it last came up, with a proportional bar — **search** by term, scope by **account/project** with the shared org→project tree picker, **sort** (Mentions / Meetings / Recent / Name), narrow by a **time-range** (last mention), optionally **group by last-mention date** into a collapsible Year → Month → Day tree with expand/collapse-all, and **Reset** it all in one click. Selecting a term opens a **drill-down**: a summary (mentions · meetings · accounts), a **tappable bar chart** of which accounts/projects mention it, and the source meetings below — **tap a bar to scope the meetings to that account** (and "Show all" to clear). So you see who's talking about a competitor at a glance, then drill into the exact conversations. Add terms with a prominent inline field. Re-scans note bodies against your *current* watchlist, so terms you add later surface retroactively. Offline, no AI cost.
- **Smart Titles:** Finished meetings get a concise AI-generated `title:` in their front-matter (e.g. "Acme SSO Migration Scoping") instead of a bare timestamp — shown in the viewer and Catalog. The on-disk filename stays `Meeting_<timestamp>.md`, so links never break. Cloud-gated; Local-only keeps the timestamp.
- **Draft Documents from a Meeting:** From any meeting note, draft a document via the **Draft…** menu — the *output document type* is its own axis, separate from the meeting type. The menu leads with **Suggested** documents for the note's meeting type (a Solution Demo suggests Follow-up Email, POC Plan, Proposal), then lists all 13 built-in types grouped as **Email & Recap** (Follow-up Email, Quick Recap, Thank-You Note), **Records** (Minutes of Meeting, Decision Log, Action-Item List), **Sales** (Proposal / Next Steps, POC Plan, Talking Points), **Reports** (Status Update, Executive Summary, FAQ), and **Retro** (Retrospective) — plus your own custom types, or **Auto — match meeting type**, which shapes a follow-up to the meeting template (a customer call → client email, etc.; that per-template guidance is **fully editable** in Settings). Each document type **caches independently**, so one meeting can yield an MoM *and* a follow-up email *and* a status update, and switching between them is free. Each opens in the in-app editor to tweak, copy (as rich text), or save. The drafting guidance for every document type — recipient, tone, sections, format — is **fully editable** in Settings → Meetings → **Draft Templates**, with a per-type reset to the built-in default, and you can **add your own custom document types** there too.
- **Follow-Up Packet (one click):** From any meeting note, the Draft… menu leads with **Follow-Up Packet** — a single grounded document that bundles the three things you send after a call: a **client follow-up email**, an **updated POC plan**, and the **action items**. The POC plan is grounded in the linked project's *current success criteria* (a status snapshot from the Catalog — passed / pending / failed — plus AI next steps focused on the unmet ones); action items reuse the note's own curated `## Action Items` when it has them (no token spend), and are drafted from the transcript otherwise. The sections generate concurrently and each degrades to an inline note if it fails, so the packet always assembles. It opens in the in-app viewer to read, **Regenerate**, copy as rich text, or **export the whole thing as one PDF**. Because it fires several AI requests at once, it asks for a **one-time confirmation** first (with "Don't ask again"). Settings → Meetings → **Draft Templates → Follow-Up Packet** is a pick-and-reorder list: add *any* draft-document type, remove, or move sections up/down (order = order in the document); the curated three keep their special grounding wherever they sit. (Cloud AI; hidden in Local-only mode.)
- **Template Import / Export:** Back up or share your customisations as one portable `.json` bundle — your custom meeting templates, custom document types, and any edits to built-in guidance (built-ins themselves aren't included). Import offers **Merge** (add/update by id, keeping your others) or **Replace** (swap all custom template data), mirroring the Catalog's import UX. Lives in Settings → Meetings → **Meeting Templates** (a pane split out of Notes & Summaries so both template editors sit together).
- **Auto-Tagging & Entities:** After summarizing, GhostWriter extracts 3–6 topic tags **plus the named entities the meeting is about** — attendees, customer/client, and project — and writes them into the note's YAML front-matter: mirrored into `tags:` for instant Obsidian/Notion graph links, and as structured `attendees:` / `customer:` / `project:` fields for Dataview-style filtering. On by default. Person names are only harvested when redaction is off, so a privacy-conscious setup never captures them.
- **Live Meeting Assistant:** An opt-in floating brief that rides along while a meeting runs — a rolling TL;DR and the open action items so far, refreshed as the conversation develops (cost-aware: only re-briefs on meaningful new dialogue, and never runs in Local-only mode). **Ask** a grounded question about the meeting so far and get an answer from the live transcript. Click the header to collapse it to a minimal strip, clear the Q&A, or hide it entirely and reopen from the menu. On by default when you're set up for cloud transcription.
- **Agendas, Static & Dynamic:** Type an optional agenda when you start a meeting (comma-separated). The Live Brief panel shows a **coverage checklist** — and *also surfaces topics the meeting itself raised* that you didn't list (marked with a ✨), so the agenda builds itself even when you start with a blank one. You stay in control of completion: items are ticked **by tapping** (the model surfaces topics but never auto-marks them done, so nothing flips green on you); tap a discovered topic's **✕** to dismiss it as noise (it won't come back or reach the notes). The final agenda — planned items and kept discovered ones, each checked or not — is written into the notes as its own **`# Agenda`** checklist.
- **Ask Before It Ends:** When you deliberately end a meeting, GhostWriter checks the agenda and — if anything's still unticked (agenda items or discovered topics you haven't marked done) — offers **Keep Recording / End Anyway** with the list, so nothing important slips through. Reuses the live panel's state when it's running (no extra call); otherwise a one-shot check. Cloud-only and best-effort; skipped for very short meetings and in Local-only mode.
- **Cost Controls:** A **Lightweight-tasks model** setting routes high-frequency background work (live brief, agenda coverage, auto-tagging, search-term expansion) to a cheaper/faster model (`llama-3.1-8b-instant` by default) while summaries, follow-ups, and Ask stay on the polishing model. Set an optional **monthly budget** and GhostWriter tracks month-to-date spend, shows a progress bar, flags `⚠️ over budget` in the menu, and notifies once when you cross it — a soft cap that never blocks transcription.
- **In-App Notes Viewer/Editor:** Open any note in a built-in Markdown editor. Notes open **read-only** by default in a rendered preview with three navigation aids: a **⌘F find** that highlights just the matched word/phrase inline (not the whole line) and steps through matches (next/prev); a **Contents** sidebar — a table of contents listing section headings and, badged with a clock, the meeting's topic chapters, each click-to-jump; and **clickable chapter bullets** in the note body, which scroll straight to that moment in the transcript by matching the chapter's timestamp. The footer keeps everyday actions (edit, contents, find, copy, summarize, draft) one click away and folds the rest (Export PDF, Open in Default App, Reveal in Finder, Rename Speakers) into an overflow menu. Click **Edit** to switch to the raw Markdown, which uses the **native find bar** with **find & replace** (⌘F, ⌘G / ⇧⌘G to step). Then edit and save, or **export to a formatted PDF** — a designed document (styled in the app's own navy/cyan palette) with a title header, a **Properties** box (meeting type, date, organisation/project resolved from the Catalog, attendees, tags), a **clickable table of contents** whose entries jump to their section, per-section hairline rules, page-numbered footers, and a **POC Success Criteria** section (with the linked project's criteria) appended at the end and listed in the contents. A **Summarize** button opens the note's AI **brief** — key-point bullets plus **Next Steps** and **Action Items** — in its own window, with a **Regenerate** button to discard the cached copy and produce a fresh one. This is the same structured artifact the Catalog's relationship digest uses (generated once per note, then reused). Works on-device in Local-only mode. Reachable from the menu, the Catalog, and Ask results.
- **Note Viewer:** Notes open in a built-in viewer that **renders the Markdown** when reading — headings, bullet and task lists (with checkboxes), block quotes, code, rules, inline bold/italic/links, and a compact Properties box for the YAML front-matter — and switches to a raw monospaced editor (with ⌘F find & replace) when you unlock to edit. Prefer your own editor? Turn on **Open notes in external editor** (Settings → General) and every note-open — menu, recent list, Catalog, Ask — hands off to your default `.md` app (VS Code, Obsidian, Typora, …).
- **On-Device AI (Apple Intelligence + NaturalLanguage):** Text AI can run entirely on-device. **Summaries, briefs, and follow-up drafts** use Apple's **Foundation Models** LLM (macOS 26+ on capable hardware); **topic/entity tagging** uses macOS **NaturalLanguage** NER (people, organisation, topics), which works on *every* Mac. On-device is used three ways: automatically in **Local-only mode**, as a **fallback** when Groq is unreachable or rate-limited (cloud results seamlessly fall back to Apple), and whenever you opt in with **Prefer on-device AI for summaries & drafts** (Settings → General) — which keeps Groq for transcription while generating text privately and for free on-device. On-device output is tagged "_generated on-device with Apple Intelligence_" so the source is always clear.
- **AI Response Cache:** Note briefs and follow-up drafts are cached to `~/Library/Application Support/GhostWriter/AICache.json`, keyed by the note's content hash + model + prompt version — so reopening a summary or relationship digest costs nothing, and a cosmetic edit (a new tag, reordered attendees) won't force a re-generation. Edits, model changes, or prompt updates invalidate automatically. Regenerate buttons force a fresh copy; **Settings → Usage & Cost → Maintenance → Clear Cache** wipes it. Fully rebuildable, so it's excluded from backups.
- **Local-Only Mode:** A hard privacy switch — transcribe on-device (Apple Speech) *and* run text AI on-device (summaries, briefs, and follow-ups via Apple Intelligence when available; topic/entity tags via NaturalLanguage always). No API cost, and nothing leaves the Mac. Dictation polishing is still skipped, and transcription accuracy is lower than the cloud. Settings shows whether Apple Intelligence is available on this Mac.
- **Auto-Redaction:** Optionally scrub emails, phone numbers, and long number sequences from transcripts before they're typed, saved, or sent to the LLM — replaced with `[redacted …]` labels.
- **Usage & Cost Estimate:** Local counters track audio transcribed and LLM tokens, with a running Groq spend estimate (editable prices) — all-time and month-to-date — in Settings and at a glance in the menu, plus an optional monthly budget with warnings.
- **Error Surfacing & Diagnostics:** Failures post a notification, show a dismissable banner in the menu, and collect in a Diagnostics pane — no more silent gaps.
- **Meeting History & Dictation Recall:** Browse past meetings from the menu bar or the Catalog; ⌃⌥V re-types your last dictation (great when you dictated into the wrong field).
- **Per-Site Browser Styling:** Reads the active browser tab's address (Safari + Chromium; opt-in, Automation permission) so a website gets its own writing style — e.g. Gmail uses Email, GitHub uses Code — via a row editor (host field + style picker) backed by editable `host: style` rules.
- **Dictation Archive:** Optionally save every dictation to its own Markdown file with metadata front-matter (app, host, style, duration, words), organized into dated subfolders (its own layout, independent of meetings). Browse them from the menu bar → **Dictations…** — a **master–detail browser**: a searchable, **app-filterable**, sortable (newest/oldest), day-grouped list on the left (each row shows app, style, time, a two-line text preview, duration and word count) with a live **stats bar** (count · total time · total words for the current filter); selecting a row shows its **full text** on the right with first-class actions — **Copy** (the polished text straight to the clipboard, with a "Copied!" confirmation), **Open** in the editor, **Reveal** in Finder, and **Delete** (Move to Trash). A **Select** mode adds per-row checkboxes with **Select All** / **Clear Selection** plus **Copy Selected**, **Delete Selected**, and **Delete All** (deletes move files to the macOS Trash, recoverable; bulk actions respect the current filter). The toolbar uses compact icon buttons with tooltips. **Reload** re-scans on demand (and on window focus) so dictations deleted on disk drop off.
- **Custom Vocabulary & Replacements:** Feed Whisper your names, acronyms, and jargon, plus post-transcription find→replace rules — domain terms transcribe correctly.
- **Catalog-Aware Transcription:** When a meeting is linked to a Catalog org or project, GhostWriter primes Whisper with that context's proper nouns — the organisation and project names, the people on its recent notes, and the voice identities you've taught — so those names transcribe correctly **from the first mention** (not only after they first appear via self-priming). Cleared when the meeting ends, so it never leaks into the next.
- **Offline Fallback:** If Groq is unreachable, transcription falls back to Apple's on-device speech recognition — dictation keeps working with zero network.
- **Retry Queue:** Meeting segments that fail to transcribe (network blips) are retried automatically with backoff; anything unrecoverable becomes a visible `⚠️ transcription failed` marker in the notes instead of a silent gap.
- **Ask Your Notes:** A multi-turn chat grounded in your meeting archive, opened from the menu. Pick a **scope** — all meetings, a chosen set, or a specific organisation/project — then ask. Relevant excerpts are retrieved with **hybrid retrieval** — blending on-device semantic similarity (meaning) with a BM25 keyword score (exact names/IDs), reranked with an exact-phrase bonus and a recency nudge, and working even when no OS embedding model exists — and each answer **cites** which meeting its points came from, with the source files listed underneath. Semantic search is powered by Apple's local `NLEmbedding` (free, private, no network) and falls back to keyword search when no OS embedding model is available. (Day-by-day browsing, Text/Meaning search, and action-item review with Reminders export live in the **Catalog** and **Today's Digest**.)
- **Catalog:** A lightweight CRM-style organiser that sits *beside* your notes without touching them — a graph of the **organisations, people, hierarchical projects and tags** your meetings are about. Open it from the menu (**Catalog…**). A three-column browser (sections → list → editor) plus a **Map** tab that renders the whole thing as one searchable tree — `Org → Project → (sub-projects) → Note → {People, Tags}` — with **Expand-all / Collapse-all** controls, auto-expand while filtering, and notes listed newest-first. The Map also carries the shared toolbar: an **org→project scope picker** (re-roots the tree at one account/project), a **time-range** filter (prunes branches with no notes in the window), and **Show people / Show tags** toggles to simplify the tree to just `Org → Project → Note` — plus a **Reset** that clears the search, scope, range, and visibility at once. Every record list (organisations, projects, people, tags) has its own **text filter**; projects are grouped by organisation; and inside a note's editor the **project, organisation, people, and tag** pickers all filter too, so assigning is fast even with long lists. Each organisation and project offers a **Summarize relationship** button — a one-tap AI digest across its most recent notes ("where things stand", decisions, open threads, risks) opened in its own window, with a **Regenerate** button to refresh it. Each meeting's block is the *same* cached brief the notes-viewer Summarize produces (one AI call per note, reused for both), so the digest is cheap to reopen. Runs on-device in Local-only mode. Organisations form an **unlimited hierarchy** (each with an editable relationship: Root / Customer / Prospect / Partner / Internal / Other); projects are themselves an **unlimited hierarchy** (sub-projects); a **root project always belongs to an organisation** (mandatory), and sub-projects inherit their org up the chain. Every org/project chooser in the app — Assign, Ask scope, audio-import "File under", the Notes / Open Questions / POC Tracker filters, the Dashboard account filter, and the Start-Meeting link — is the same searchable **indented org→project tree**, so navigating the hierarchy is identical everywhere. **Notes are assigned to a project *or* an organisation** (mutually exclusive), and the project → parent → org chain is **inherited automatically**. **People and tags are set per note** — each note owns its own set, picked or created inline like tags (people are independent of orgs; an org's people are simply whoever appears on its notes). **Import notes** pulls in your meeting files (`Meeting_*.md` only). A note's editor is **chip-based**: a **Filed under** row shows the assigned project/org as a removable chip with a single searchable **Assign…** picker (project *or* org); **People** and **Tags** are removable chips with a searchable **Add…** that creates on the fly; a **From this note** section turns words the note suggests into any entity type; and its **action items** tick + export to Reminders (individually or all at once). Search notes with the **Text** / **Meaning** (on-device semantic) / **Ask** (a cloud Q&A scoped to the filtered notes, with cited sources that open in the editor) modes, and scope by account/project with the **same shared org→project tree picker** used across the app (header, top-right), and refine further with a single **Filter** menu — badged with the active count — that folds the remaining facets (person, tag) plus **Unassigned** and **Missing** (file gone from disk) triage presets into one control; active filters show as removable **chips** under the search field. When browsing (no active search) the list is a **collapsible Year → Month → Day tree** — newest first, the current month's days expanded, per-group counts, undated notes pinned to the bottom, with an **Expand all / Collapse all** toggle — scoped by a compact **time-range** dropdown at the top-right (Today / 7 days / **30 days · default** / 90 days / 6 months / 1 year / all, shared with the dashboard); a live search flattens it to a ranked result list. A one-click **Reset** clears the search, filters, and range together (it appears whenever anything is off-default). Note rows expose inline **reveal** and a **trash menu** — *Remove from Catalog* (drops the row, keeps the `.md` file), *Move to Dictation…* (reclassifies the note into the dictation archive — useful for an imported clip that wasn't really a meeting), or *Move Note to Trash…* (confirms, then sends the file to the macOS Trash and removes the row — recoverable). Missing-file rows offer only the row removal. The footer offers **Import / reload** and **clean-up** for entries whose Markdown file was deleted. Each organisation and person shows a **relationship timeline** — their notes newest-first, dated and click-to-open — so the whole history is one glance. Starting a meeting linked to an org/project pops a small **prep card** — a non-modal floating panel listing that entity's most recent notes (click any to read the full note while the meeting records). No extra input — it's driven by the link you pick in the Start dialog, and skipped when there's no prior history. **Quick add** builds a whole org → project → people → tags chain (with a parent) in one sheet. **Export / Import** the whole catalog as a portable `Catalog.json` — export is a drop-in backup; import offers **Merge** (upsert every record by id, keeping the rest) or **Replace** (swap the entire catalog), never touching your note files. Stored as a single `Catalog.json` in the notes folder — rebuildable, backup-friendly, with a **Purge** action that clears the catalog while leaving your note files intact.
- **Open Technical Questions:** A cross-meeting queue in the **Catalog** (sidebar → Track → **Open Questions**) of every unresolved question pulled from your notes' *Open Questions* sections (also recognizing the legacy *Unanswered Questions* heading in older notes) — your follow-up list across all accounts. **Grouped by date into a collapsible Year → Month → Day tree** (newest first, the current month's days expanded, per-group counts, and an **Expand all / Collapse all** toggle); each day lists its notes, and each note shows its open count and opens on click. A compact **time-range** dropdown (Today / 7 days / **30 days · default** / 90 days / 6 months / 1 year / all — the same options as the dashboard) narrows the window; search it and filter by **organization** or **project**; click any question's text to jump to its source note. **Mark a question answered** with its leading checkbox — it ticks the `- [x]` in the source note, strikes the row through, and drops it from the open count; an **Answered** toggle in the toolbar brings resolved questions back into view, and the same checkbox flips them open again. (The dashboard's "Open technical questions" card is a 5-item teaser that counts only still-open questions.)
- **POC Tracker:** For technical pre-sales, track proof-of-concept **success criteria** across meetings. It lives in the **Catalog** (sidebar → Track → **POC Tracker**). A **project can hold several POCs** (e.g. "Security evaluation", "Scale test"), each with its own criteria, lifecycle phase, and timeline; the tracker is a flat list of **POCs** (one row per POC, not per project). The **list** is a tracker in its own right: a **stats strip** across the top (total POCs, at-risk, complete, a **due-soon/overdue** count, and an overall passed/total criteria progress bar), a **search** box, the shared **org→project tree picker** to scope by account/project (same as the dashboard), a badged **Filter** menu (a labeled **Status** selector — **Open** (planned/in-progress/on-hold, the **default** so closed POCs are hidden) / Closed / All, or a **specific phase** (Planned / In progress / Passed / Failed / On hold) — plus a **health** filter in the funnel menu), a **＋ New POC** button (pick the owning project, name it), and **Group by** (Phase / Health / **Account · default** / Project / **Date** / None) + **Sort** (At-risk first / **Deadline** / Name / Progress / Recent activity) dropdowns. Grouping by **Date** buckets POCs into a collapsible **Year → Month → Day** tree by last meeting activity (same control as Notes); all groupings are **collapsible** with an expand/collapse-all toggle, and a one-click **Reset** restores search, filters, group, sort, and range. Each POC row shows a **health icon** (At risk / In progress / Complete / Not started / No criteria), its **phase pill** (Planned / In progress / Passed / Failed / On hold), the owning project + account path, a mini progress bar with passed/total (and a failed count), a **deadline pill** when a target date is set (green/orange/red as it nears or passes — "Due in 3d" / "Due today" / "Overdue 2d"), and how long ago it was last touched — and a chevron **expands the row to reveal the project's linked meeting notes** (date + title, click to open). Pick a POC to open it on the right: an **editable name**, a **phase** picker, **start + target date** controls (each defaulting sensibly, editable, clearable), an optional **description** ("what must this POC prove?"), and the **success criteria** themselves. **Criteria form an unlimited hierarchy** — every criterion has a **＋** to add sub-criteria beneath it (one per line to add several at once; indent to nest deeper), sub-trees **collapse/expand** with a chevron (plus an expand/collapse-**all** toggle above the list), and a parent shows a rolled-up passed/total of its descendant leaves while only **leaf** criteria carry a pass/fail (so nothing is double-counted). Cycle each leaf **Pending → Passed → Failed** with a single click; **double-click a criterion (or its ✏️)** to edit its text inline; **▲/▼** reorder a criterion among its siblings (its sub-tree moves with it); removing an item takes its whole sub-tree. Every criterion also has an **optional description** — click its **text/notes icon** to expand an inline description field (hidden by default to keep the list scannable); once set, a one-line preview shows under the title even when collapsed, and the description flows through to the Markdown and PDF exports. Add criteria one at a time, or **Bulk add** — paste a whole list (one criterion per line; **indent** lines with spaces/tabs to nest them to any depth; `* `/`- `/`1.` bullets are stripped). Line breaks are the only separator, so a criterion may freely contain commas. The detail pane also carries **Clear all criteria** (empties *this* POC's criteria, keeping the POC and project) and **Delete POC** (removes just this POC), each behind a confirm. A progress bar shows passed/total and flags when **all criteria are met**. **Suggest from meetings** reads the project's linked meeting notes and adds the criteria they mention at the top level (deduped, fully editable/removable). **Share / export** is built in at both levels: a per-POC **Share** menu (in the detail pane) offers **Export PDF…** (a **designed, paginated document** — a cyan→teal→blue gradient banner with the POC name and account, colour-coded KPI tiles, a progress bar, a phase pill and deadline pill, and a hierarchical, status-colour-coded criteria list with green/red/grey status chips and indented sub-criteria) and **Save Markdown…**; and a list-level **Share** menu exports **every POC in the current view at once** (respecting the active filters/scope) as one roll-up report — copy, PDF (a summary KPI strip atop numbered per-POC cards), or Markdown. PDFs are rendered natively (SwiftUI) and paginated block-by-block, so a chart, table, card, or criterion row is never split across a page boundary — staying crisp and correctly oriented. State is stored per project in `Catalog.json` (catalogs from before multiple-POCs migrate automatically — the old single set becomes one POC), so it persists and travels with the catalog.
- **Catalog Dashboard:** The Catalog opens on its **Dashboard** by default (sidebar → Overview → **Dashboard**) — a single full-width canvas built for the sales-engineer workflow. A **filter bar** at the top scopes every note-scan insight by **time range** (Today / 7 days / **30 days · default** / 90 days / 6 months / 1 year / all) and by **account** — a searchable dropdown that lays your organisations out in their **parent → child hierarchy** (indented) for easy navigation, and scopes a chosen account plus its descendants — with a live meeting count, a refresh, and a **Reset** button (appears only when a filter is off-default) that restores the defaults (**30 days**, all accounts). Below it, an **"At a glance"** strip of KPIs (organisations, open projects, active POCs, POC pass-rate, open pipeline by currency, linked notes) sits above the card grid and **honors both filters**: with **no time range** ("All time") it's the structural snapshot of your whole book of business (matching the sidebar counts); pick a **time range** and it reflects what happened in that window (entities touched by a meeting in range), and an **account** scopes it to that org and its descendants — the header spells out the active scope ("At a glance — <account> · <range>") so a windowed number is never mistaken for a catalog total: a **POC Command Center** (passed/pending/failed criteria, progress, at-risk POCs, a **due-soon / overdue** count and per-POC deadline pills, and an "at-risk only" toggle), **Relationships** (most-engaged accounts + accounts going quiet), **Activity** (meeting count/time + a 6-week trend chart), **Action Items** (open vs. overdue across recent meetings), **Meeting-Type Mix** (a technical-cycle funnel — Discovery → Demo → Scoping → Kickoff — showing where engagements cluster and where they drop off, plus an "other meetings" breakdown), **Competitive & Product Intelligence** (a Keyword-Radar mentions chart), and **Open Technical Questions** (the unanswered-questions follow-up queue, click-through to the meeting). The catalog snapshot renders instantly; the note-scan insights load in the background, and every card — including the KPI strip and POC command center — re-scopes to the selected range and account once the data lands. Charts use Swift Charts.
- **Reports:** A dedicated reporting surface (sidebar → Overview → **Reports**) that composes the same offline insights the Dashboard shows into a **professional, selectable report**. Give it a **title**, scope it with the shared **org→project tree picker** and a **time range**, then tick exactly the **insight blocks** you want (Overview KPIs, Pipeline, POC status, Activity, Relationships, Meeting-type mix, Action items, Open technical questions, Keyword intelligence — with **All / None** shortcuts). A **live preview** renders as you change scope or selection, with **visual representations** — KPI tiles, proper tables, and **bar charts** (open value by account, POCs by phase, meetings-per-week trend, the technical-cycle funnel, and top keyword mentions) drawn with Swift Charts. Everything is one report model rendered three ways: **Export PDF** (renders the native tables-and-charts view, paginated block-by-block onto US Letter or A4 pages per **Settings → General → PDF Export**, so nothing is split mid-chart and the PDF matches what you see), **Save as Markdown** (`.md`), and **Copy** (as rich text). Fully offline — no AI/cloud. Structural blocks (KPIs, pipeline, POC status) reflect the current catalog within the chosen account/project; activity-based blocks (activity, relationships, meeting mix, action items, questions, keyword mentions) reflect the selected time window.
- **Integrations (event hooks):** Fire an outbound event the moment a meeting is saved, so you can wire GhostWriter into your own tools. Two opt-in destinations (Settings → System → **Integrations**): a **local script hook** (runs your executable with the event JSON on stdin — no network) and an **outgoing webhook** (HTTPS POST). The payload carries note metadata only — title, date, meeting type, the linked org/project, and tags — never audio, and free-text fields pass through your redaction settings first. Both are **suppressed in Local-only mode**.
- **Backup & Restore:** One `.zip` snapshot of *everything* GhostWriter stores — meeting notes, quick notes, dictations, and the Catalog — from **Settings → General → Backup**. Move it to another Mac or keep it as an archive; **Restore** merges a backup back into your current folders (same-name files overwritten) and re-indexes the Catalog against the restored notes. Uses the system `zip`/`unzip`, so it's dependency-free, and restores into your *currently configured* folders rather than the paths baked into the archive.
- **Usage Stats:** Local-only counters — dictations, words typed, meetings recorded, meeting time, plus a Groq cost estimate — shown at the top of the menu and in Settings → Usage & Cost.
- **Echo Suppression:** When you're on the built-in speaker instead of headphones, half-duplex gating stops the remote party's voice (picked up by your mic as echo) from being mislabeled as "You".
- **Voice Diarization (experimental):** Label distinct remote voices (Them / Them 2 / Them 3) by fingerprinting each segment's voice — pitch via autocorrelation plus timbre — and clustering, fully on-device. **Rename Speakers…** gives them real names per meeting: the notes file is rewritten, and a live meeting keeps using the new names.
- **Persistent Voice Identities:** Rename a speaker once and GhostWriter **remembers that voice** — the next meeting where they show up is auto-labeled with their real name (e.g. "Them 2" → "Priya"), before the summary and tags are even written, so names flow everywhere. Fully on-device: each meeting's voice fingerprints are matched against your saved identities; a rename teaches a new one. No enrollment step — it learns from the renames you already do.
- **Ask Your Notes (knowledge-base chat):** A persistent, **multi-turn** chat over your meeting archive, opened from the menu (**Ask Your Notes…**). Ask "What did we decide on pricing with Acme?" or "What are my open commitments to the platform team?"; each answer retrieves the most relevant excerpts with **hybrid retrieval** (on-device semantic similarity blended with a BM25 keyword score, reranked with an exact-phrase bonus and recency; works with or without an OS embedding model) and **cites the meetings** it drew from — each citation showing the matched snippet with your terms highlighted, click-to-open. A **scope selector** narrows the search to *all meetings*, a *chosen set of meetings*, or a specific *organisation/project*. Follow-up questions carry the conversation, so "what about their timeline?" resolves against the previous turn. Runs on Groq, or fully on-device (Apple Intelligence) in Local-only / prefer-on-device mode.
- **Proactive Digest:** An optional scheduled rollup — **daily or weekly** — presented in an **interactive window**: the meetings you held (click to open), your **open (and overdue) action items** gathered from across recent meetings (tick them off in place, with owner/due pills and overdue highlighting), and the **Catalog relationships that have gone quiet** (no contact in N days). A copy is archived as a `Digests/` note, and a click-to-open notification opens the window. Assembled entirely on-device (no tokens). Open it anytime from the menu → **Today's Digest**.
- **Action Items as First-Class Tasks:** End-of-meeting summaries emit structured task lists (`- [ ] <action> — @owner (due: date)`); the Catalog and Today's Digest show them as clickable checkboxes with **owner** and **due-date** pills — marking one done writes `- [x]` back into the notes file. Push open items to **Apple Reminders** individually or all at once, with the due date carried over.
- **Organized Notes:** Meeting files are filed into dated subfolders — `Notes/2026/2026-07/03/` by default; switch to year/month, year, or a single flat folder in Settings. History, search, and stats find files in any layout.
- **Global Shortcuts:** Push-to-talk dictation (hold Right Option — or switch to tap-to-lock / toggle activation for hands-free long dictations), Esc to cancel a dictation, ⌃⌥M to toggle Meeting Mode, ⌃⌥P to pause/resume transcription, ⌃⌥N to open the notes — all system-wide, from any app.
- **Native macOS Integration:** Built entirely in Swift. CoreGraphics event taps for global hotkeys, Accessibility (`AXUIElement`) for text injection.
- **Settings Window:** A System Settings-style sidebar UI — configurable AI models, push-to-talk key, meeting overlay mode, speech-detection thresholds, notes folder, and speaker labels. Everything persists and applies live. A cross-pane **search** finds any setting by label or synonym.
- **Essentials pane:** The Settings window opens on a first-run readiness dashboard — a live three-step checklist (Groq API key, Microphone, Accessibility) that flips to "You're all set" once granted, a reminder of your current dictation gesture, and the notes-folder path. Every row deep-links into the pane with the full controls, so getting started never means hunting the sidebar.
- **Guided Permissions:** A live permission-status panel and menu items to authorize Microphone, System Audio Recording, and Accessibility, plus a one-click **Reset All Permissions** that clears the TCC grants and relaunches for a clean re-prompt.
- **Secure Key Management:** Your API key is verified against the Groq API at setup and stored in the macOS Keychain — never on disk in plain text.
